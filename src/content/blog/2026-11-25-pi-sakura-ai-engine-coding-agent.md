## 概要

普段使っているパーソナル AI エージェント Muse の実行環境（VM）に、コーディングエージェントの Pi を入れた。推論側はさくらの AI Engine で、モデルは DeepSeek-V4.1-Flash-1017。

狙いはもう1つ実装エージェントを増やすことではなく、Pi の役割をコードレビューのセカンドオピニオンに限定することだった。実装と一次判断は主エージェントが担い、Pi には差分を渡して別視点の指摘だけをもらう。

理由は単純で、書いた本人（モデル）が自分の差分を見直すより、別のモデルに見せたほうが見落としを指摘してもらえるから。

## なぜ Pi だったか

候補はひと通り見た。

- Aider は開発が止まっているので外した
- Claude Code はさくら側で使えるモデルが限られ、使いたい DeepSeek を使えない
- Codex CLI は API の形式がさくら側の制約と合わない
- OpenCode は多機能だが、サーバー常駐やセッション管理が増える

Pi は道具が read / write / edit / bash の4つだけと最小構成で、システムプロンプトも短い。印刷モードや JSON モードで無人実行できるので、VM の中から主エージェントに駆動させる形に一番合っていた。

サブエージェントを持たないことも、選んだ理由の1つだった。次の節に関係する。

## なぜさくらの AI Engine か

基盤モデル無償プランは、Chat Completions が月3,000リクエストまで無料。課金単位がトークンではなくリクエスト数であることが、このプランの要点だ。

つまり評価軸は「何トークン使ったか」ではなく「1タスクで何リクエスト消費するか」になる。サブエージェントが自動で探索してリクエストを増やす構成は、この枠では相性が悪い。Pi の消費が読みやすいのは選定理由の1つだった。

もう1つはデータの扱い。ZDR（Zero Data Retention）で、入力と応答は保存されず学習にも使われない。処理は国内のデータセンターで完結する。

とはいえ、運用ルールとして投入するのは個人のものと公開リポジトリだけにした。仕事のコードは対象外。

## 組み込み方

Pi はカスタムプロバイダ設定で、さくらの OpenAI 互換 API に直接つないだ。

トークンは設定ファイルに書かない。保管庫に登録した接続から、起動時に都度クレデンシャルを取得して環境変数で渡すラッパースクリプトを用意した。実トークンをファイルやチャットに残さない形にした。

## 実測

疎通確認は1リクエストで、応答まで9.2秒。推論モデルのため、返ってきた completion の大半は reasoning（思考）だった。`max_tokens` は思考分を見込んで大きめに取る必要がある。

小さな修正タスク（1ファイルのバグ修正、テストで合否判定）では、Pi の無人実行が4リクエストで完走した。内訳は bash 2回、edit 1回、最終報告1回。入力合計は約12,000トークン。

実リポジトリでも試した。自作の算数アプリの PR レビューを読み取り専用で渡したところ、約5分で完走し、中程度の指摘5件と軽微な指摘6件が返ってきた。ロック中の再描画で見た目が戻る余地など、自分では見落としていた堅牢性の指摘が有効で、実際に修正へ回した。

「無料枠で実務のレビューが回るか」という問いには、現時点では回ると答えられる。

## ハマったところ

### 1. 標準入力を開いたままにすると固まる

無人実行（`-p`）で Pi を起動するとき、標準入力を閉じていないと入力待ちで無言のまま固まる。2回再現して特定した。対策は `< /dev/null` で起動することだけ。

エラーを出すわけでもなく、ただ止まる。調べるのに時間がかかる。

### 2. reasoning_effort の medium がない

Pi の思考レベルの既定値 `medium` を送ると、さくらの DeepSeek が400エラーを返した。エラーメッセージを読むと、受け付けるのは low / high / xhigh / max、または1〜100の整数だけだった。

公式マニュアルの reasoning 制御の表には DeepSeek の行自体がないので、マニュアルだけでは分からない。API のエラーが一次情報だった。

今は両モデルとも思考レベルを high に固定して運用している。

## 現在の運用と次の検証

常用の道具は Pi で確定し、モデルは DeepSeek がメイン。

コード特化の Kimi-K2.7-Code も同じ枠で使えるので気にはなっている。ただ、さくらのマニュアルでは処理時間の上限で打ち切られやすいモデルとして名指しされているし、この環境での実績もまだない。即切り替えはせず、次の PR レビューで同じ差分を両モデルに渡す A/B 実測をしてから決める予定。

結果が出たら続編を書く。

## Muse に頼む場合のプロンプト

自分の Muse に同じ構成を頼む場合は、次のプロンプトをそのまま渡せばよい。さくらの AI Engine の利用開始とトークンの発行だけは、本人の作業になる。

```text
あなたは私のパーソナルエージェントです。あなたの実行環境に、コードレビュー専用のコーディングエージェント環境を構築してください。

構成:
- エージェント: Pi（@earendil-works/pi-coding-agent）
- 推論 API: さくらの AI Engine（OpenAI 互換の Chat Completions）
- モデル: preview/DeepSeek-V4.1-Flash-1017
- 役割: 実装ではなく、PR の差分レビュー（セカンドオピニオン）に限定します

進め方:
1. まず設計と検証計画だけを提示し、私が「go」と言うまでインストールや申込はしないでください。
2. トークンはチャットに貼らせず、安全な保管方法で受け取ってください。実トークンを設定ファイルやログに書かず、起動時に環境変数で渡すラッパーを作ってください。
3. 対象は個人のリポジトリと公開リポジトリのみです。仕事のコードは投入しません。
4. 無料枠は月 3,000 リクエストまで（トークンではなくリクエスト数）という前提で進め、1 タスクの消費リクエスト数を実測して報告してください。
5. 検証は、疎通確認 1 回、小さな修正タスク、実 PR の読み取り専用レビューの順に行ってください。
6. 無人実行では標準入力を閉じて起動してください。開いたままだと入力待ちで止まります。思考レベル（reasoning_effort）は high に固定してください。medium は API に拒否されます。
7. 結果は、消費リクエスト数、所要時間、モデルの指摘内容を含めて報告してください。
```
